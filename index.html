A kernel-based root solution for Waydroid

KernelSU-Next packaged as a loadable kernel module and built with DKMS — root inside Waydroid on stock CachyOS kernels, no custom kernel required.

Get started View on GitHub

Kernel module, not a kernel patch

KernelSU-Next ships as a loadable module built with DKMS against your running kernel — no custom kernel, no SUSFS, nothing to maintain across updates.

Build with DKMS

kernelsu.ko compiles against $(uname -r) headers and auto-rebuilds on every kernel update.

Loads on stock kernels

Loaded via modloader instead of modprobe, which can't resolve the PID-namespace symbols the module needs.

Root access control

Only permitted apps see su. The Manager app (com.rifsxd.ksunext) grants and manages root.

Auto-load & stage

systemd services load the module at boot and stage su/ksud into the Waydroid container so apps get a working su.

       host Linux kernel                   Waydroid LXC container (x86_64 / Android)

Install

Quick install (one-liner)

curl -fsSL https://raw.githubusercontent.com/Polaricito/KernelSU-Next-DKMS/master/installer.sh | sudo bash

From a checkout

git clone https://github.com/Polaricito/KernelSU-Next-DKMS.git
cd KernelSU-Next-DKMS
sudo ./install.sh

Options

FlagEffect
--kernel <ver>Target a specific kernel version (default: uname -r)
--skip-seccompDon't modify the Waydroid seccomp profiles
--uninstallRemove KernelSU and restore the original state
After installing: start a session with waydroid session start and install the Manager app com.rifsxd.ksunext to grant root and manage modules.

Uninstall

One-liner

curl -fsSL https://raw.githubusercontent.com/Polaricito/KernelSU-Next-DKMS/master/uninstaller.sh | sudo bash

From a checkout

sudo ./install.sh --uninstall

This unloads the module, removes it from DKMS, and deletes all installed files and services. Your kernels are left untouched.

FAQ

Do I need a custom kernel?

No. It builds as a module against your stock kernel (CachyOS stable or LTS work fine).

Why not modprobe kernelsu?

Plain modprobe fails with Unknown symbol change_pid, because the module needs PID-namespace symbols that modprobe can't resolve outside Android. load-kernelsu uses modloader and handles that.

It installs during boot, does it also unload?

kernelsu-autload.service loads the module at boot. Uninstalling removes the service so it stops auto-loading.

Version numbers / v0.0.1

The module reports KSU_VERSION = 30000 + commits. If the Manager shows a too-low version, ensure DKMS received KSU_GIT_VERSION and KSU_GIT_TAG (the installer does this automatically).

Where is SUSFS?

Removed. This is deliberately vanilla KernelSU-Next for stable, plain root on unpatched kernels.
