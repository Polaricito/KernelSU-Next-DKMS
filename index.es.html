Una solución de root basada en kernel para Waydroid

KernelSU-Next empaquetado como módulo kernel cargable y compilado con DKMS — root dentro de Waydroid en kernels CachyOS 6.x estándar (probado en 6.18), sin kernel personalizado.

Empezar Ver en GitHub

Módulo kernel, no un parche de kernel

KernelSU-Next se distribuye como un módulo cargable compilado con DKMS contra tu kernel en uso — sin kernel personalizado, sin SUSFS, nada que mantener entre actualizaciones.

Compila con DKMS

kernelsu.ko se compila contra las cabeceras de $(uname -r) y se recompila automáticamente con cada actualización del kernel.

Carga en kernels estándar

Se carga mediante modloader en lugar de modprobe, que no puede resolver los símbolos del PID-namespace que el módulo necesita.

Control de acceso root

Solo las apps permitidas ven su. La app Manager (com.rifsxd.ksunext) concede y gestiona el root.

Carga y preparación automáticas

Los servicios systemd cargan el módulo al arrancar y preparan su/ksud dentro del contenedor Waydroid para que las apps tengan un su funcional.

Instalación

Instalación rápida (una línea)

curl -fsSL https://raw.githubusercontent.com/Polaricito/KernelSU-Next-DKMS/master/installer.sh | sudo bash

Desde un clon del repositorio

git clone https://github.com/Polaricito/KernelSU-Next-DKMS.git
cd KernelSU-Next-DKMS
sudo ./install.sh

Opciones

FlagEfecto
--kernel <ver>Apuntar a una versión específica del kernel (por defecto: uname -r)
--skip-seccompNo modificar los perfiles seccomp de Waydroid
--uninstallEliminar KernelSU y restaurar el estado original
Después de instalar: inicia una sesión con waydroid session start e instala la app Manager com.rifsxd.ksunext para conceder root y gestionar módulos.

Desinstalación

Una línea

curl -fsSL https://raw.githubusercontent.com/Polaricito/KernelSU-Next-DKMS/master/uninstaller.sh | sudo bash

Desde un clon del repositorio

sudo ./install.sh --uninstall

Esto descarga el módulo, lo elimina de DKMS y borra todos los archivos y servicios instalados. Tus kernels quedan intactos.

Preguntas frecuentes

¿Qué kernels son compatibles?

Solo 6.x. KernelSU-Next upstream lista 6.6 como el kernel máximo soportado oficialmente, pero esta compilación DKMS está probada en versiones 6.x más nuevas (6.18), así que el límite no se aplica aquí.

¿Necesito un kernel personalizado?

No. Se compila como módulo contra tu kernel estándar (CachyOS stable o LTS funcionan bien).

¿Por qué no modprobe kernelsu?

modprobe falla con Unknown symbol change_pid, porque el módulo necesita símbolos de espacios de nombres PID que modprobe no puede resolver fuera de Android. load-kernelsu usa modloader y lo resuelve.

Se instala al arrancar, ¿también se descarga?

kernelsu-autload.service carga el módulo al arrancar. Desinstalar elimina el servicio para que deje de cargarse automáticamente.

Números de versión / v0.0.1

El módulo informa KSU_VERSION = 30000 + commits. Si el Manager muestra una versión muy baja, asegúrate de que DKMS recibió KSU_GIT_VERSION y KSU_GIT_TAG (el instalador lo hace automáticamente).

¿Dónde está SUSFS?

Eliminado. Esto es KernelSU-Next deliberadamente vanilla para un root estable y simple en kernels sin parchear.
